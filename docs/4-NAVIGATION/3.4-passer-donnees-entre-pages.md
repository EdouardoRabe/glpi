# 3.4 Passer des Données entre Pages

> 🔎 **Mots-clés de recherche :** useNavigate, useLocation, useParams, state, params, query string, searchParams, passer données, transmettre, envoyer données entre pages, partager données, location.state, navigation programmatique

## QUOI ?

Comment **envoyer des données d'une page à une autre** quand on navigue. Il existe **3 méthodes** — ce guide explique chacune, avec des exemples copy-paste, et **laquelle choisir**.

| Méthode | Outils | Survit au refresh (F5) ? | Visible dans l'URL ? |
|---------|--------|--------------------------|----------------------|
| **1. Param URL** | `useNavigate` + `useParams` | ✅ Oui | ✅ Oui (`/tickets/42`) |
| **2. Query string** | `useNavigate` + `useSearchParams` | ✅ Oui | ✅ Oui (`/tickets?statut=2`) |
| **3. State (objet)** | `useNavigate` + `useLocation` | ❌ **Non** (perdu) | ❌ Non (caché) |

---

## Méthode 1 — Paramètre dans l'URL (`useParams`)

Pour passer un **identifiant** (id de ticket, d'asset...). L'info est dans l'URL.

### La route (App.jsx / router)
```jsx
<Route path="/tickets/:id" element={<TicketDetail />} />
```

### Page de départ — on navigue avec l'id
```jsx
import { useNavigate } from "react-router-dom";

function TicketsList({ tickets }) {
    const navigate = useNavigate();

    return (
        <ul>
            {tickets.map((ticket) => (
                <li
                    key={ticket.id}
                    onClick={() => navigate(`/tickets/${ticket.id}`)}  // ← id dans l'URL
                >
                    {ticket.name}
                </li>
            ))}
        </ul>
    );
}
```

### Page d'arrivée — on lit l'id avec `useParams`
```jsx
import { useParams } from "react-router-dom";

function TicketDetail() {
    const { id } = useParams();   // ← récupère "42" depuis /tickets/42

    // On a juste l'id → on recharge le ticket depuis l'API
    // const [ticket, setTicket] = useState(null);
    // useEffect(() => { Ticket.getById(id).then(setTicket); }, [id]);

    return <h1>Détail du ticket #{id}</h1>;
}
```

> ✅ **Le mieux dans 90% des cas.** L'URL `/tickets/42` est partageable, marche au refresh, et on recharge la donnée fraîche depuis l'API. Voir [3.2 Paramètres URL](3.2-parametres-url.md).

## Méthode 2 — Query string (`useSearchParams`)

Pour passer des **filtres / options** (recherche, tri, page...). L'info est après le `?` dans l'URL.

### Page de départ
```jsx
import { useNavigate } from "react-router-dom";

function Filtres() {
    const navigate = useNavigate();

    const filtrerParStatut = (statutId) => {
        navigate(`/tickets?statut=${statutId}&tri=date`);  // ← après le ?
    };

    return <button onClick={() => filtrerParStatut(2)}>Voir "En cours"</button>;
}
```

### Page d'arrivée — on lit avec `useSearchParams`
```jsx
import { useSearchParams } from "react-router-dom";

function TicketsList() {
    const [searchParams] = useSearchParams();

    const statut = searchParams.get("statut");  // "2"
    const tri = searchParams.get("tri");         // "date"

    return <p>Filtre statut : {statut}, tri : {tri}</p>;
}
```

> ✅ Idéal pour les filtres : l'utilisateur peut **partager l'URL filtrée** et la retrouve au refresh. Voir [3.3 Navigation Avancée](3.3-navigation-avancee.md).

## Méthode 3 — State (passer un OBJET) ⭐ le manquant

Pour passer un **objet complet** (un ticket déjà chargé, un message...) **sans le mettre dans l'URL**. C'est `useNavigate` avec une option `state`, lu avec `useLocation`.

### Page de départ — on passe l'objet dans `state`
```jsx
import { useNavigate } from "react-router-dom";

function TicketsList({ tickets }) {
    const navigate = useNavigate();

    const ouvrirDetail = (ticket) => {
        navigate(`/tickets/${ticket.id}`, {
            state: { ticket },   // ← on attache l'objet ENTIER au déplacement
        });
    };

    return (
        <ul>
            {tickets.map((ticket) => (
                <li key={ticket.id} onClick={() => ouvrirDetail(ticket)}>
                    {ticket.name}
                </li>
            ))}
        </ul>
    );
}
```

### Page d'arrivée — on lit avec `useLocation`
```jsx
import { useLocation } from "react-router-dom";

function TicketDetail() {
    const location = useLocation();
    const ticket = location.state?.ticket;   // ← récupère l'objet (le ?. est important !)

    // ⚠️ Si on arrive ici par refresh ou lien direct, state est null
    if (!ticket) {
        return <p>Aucune donnée. Recharge depuis la liste.</p>;
    }

    return (
        <div>
            <h1>{ticket.name}</h1>
            <p>{ticket.content}</p>
        </div>
    );
}
```

> ⚠️ **LE piège à connaître :** le `state` est **perdu si l'utilisateur rafraîchit la page (F5)** ou ouvre l'URL directement. C'est pour ça qu'on met `location.state?.ticket` (avec `?.`) et qu'on prévoit un cas "pas de donnée".

## ⚠️ Le piège du refresh — pattern robuste (state + fallback API)

Le meilleur des deux mondes : on utilise le `state` s'il est là (rapide, pas d'appel API), sinon on recharge via l'id de l'URL.

```jsx
import { useState, useEffect } from "react";
import { useParams, useLocation } from "react-router-dom";
import Ticket from "../../backend/model/Ticket";

function TicketDetail() {
    const { id } = useParams();              // ← toujours dispo dans l'URL
    const location = useLocation();
    // Si on vient de la liste → state dispo. Si refresh → null.
    const [ticket, setTicket] = useState(location.state?.ticket ?? null);

    useEffect(() => {
        // On ne recharge QUE si on n'a pas déjà le ticket (cas refresh)
        if (!ticket) {
            Ticket.getById(id).then(setTicket);
        }
    }, [id, ticket]);

    if (!ticket) return <p>Chargement...</p>;

    return <h1>{ticket.name}</h1>;
}
```

> ✅ C'est **le pattern recommandé** pour une page de détail : rapide quand on vient de la liste, mais ça marche quand même si on rafraîchit ou partage le lien.

## Bonus — passer un message après une action (ex: "Ticket créé !")

Cas très courant : après avoir créé un ticket, on redirige vers la liste avec un message de succès.

### Page de création
```jsx
const navigate = useNavigate();

const handleSubmit = async () => {
    await newTicket.save();
    navigate("/tickets", {
        state: { message: "Ticket créé avec succès !" },
    });
};
```

### Page liste — on affiche le message une fois
```jsx
import { useLocation } from "react-router-dom";

function TicketsList() {
    const location = useLocation();
    const message = location.state?.message;

    return (
        <div>
            {message && <div className="success-banner">{message}</div>}
            {/* ... la liste ... */}
        </div>
    );
}
```

## Quelle méthode choisir ?

| Tu veux passer... | Méthode | Pourquoi |
|-------------------|---------|----------|
| Un **id** (ticket, asset) | **Param URL** (`useParams`) | URL partageable, recharge fraîche, survit au refresh |
| Des **filtres / recherche / tri** | **Query string** (`useSearchParams`) | Partageable, l'utilisateur retrouve ses filtres |
| Un **objet déjà chargé** (éviter un 2e appel API) | **State** (`useLocation`) | Pas dans l'URL, rapide — MAIS perdu au refresh |
| Un **message ponctuel** ("Créé !") | **State** (`useLocation`) | Temporaire, pas besoin dans l'URL |

✅ **Règle simple :**
- Donnée **importante / partageable / qui doit survivre au refresh** → **URL** (param ou query).
- Donnée **pratique / temporaire** (objet déjà en main, message) → **state**, toujours avec un fallback.

## ⚠️ Pièges courants

```jsx
// ❌ 1. Lire state sans ?. → crash si state est null (refresh)
const ticket = location.state.ticket;
// ✅
const ticket = location.state?.ticket;


// ❌ 2. Compter sur le state pour une donnée critique (perdu au F5)
navigate("/tickets/42", { state: { ticket } });  // seul moyen d'avoir le ticket
// ✅ Toujours prévoir le fallback via l'id de l'URL (voir pattern robuste)


// ❌ 3. Passer un objet ÉNORME dans state (tout l'array de tickets)
navigate("/detail", { state: { tousLesTickets: [...500 items] } });
// ✅ Passe juste ce qu'il faut (un id, ou un seul objet)


// ❌ 4. Mettre une donnée sensible dans l'URL
navigate(`/page?motDePasse=1234`);   // visible dans l'historique !
// ✅ Données sensibles → jamais dans l'URL
```
